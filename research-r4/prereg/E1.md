# E1 pre-registration — consensus termination (H1). Written 2026-10-19 23:40 Asia/Taipei, before any E1 run.

Question: does replacing unilateral per-peer exit with consensus termination (C1) remove the collapse mode and raise
quality on large open-ended dev tasks, without losing the speed advantage over solo?

Arms (murmur from /workspace/r4/lab/repos/murmur.git, 3 peers, gpt-6-astra, effort high, cap 120m):
- base4 = 146d476 (fix/r3-reliability)
- C1    = 76d8b44 (experiment/r4-c1: base4 + peer.md requirements ledger, park-with-wait_agent instead of ending the
  turn, END quorum on the same latest main commit, followup_task to wake idle peers with open items). Prompt-only.
- solo  = plain `codex exec` (runner "exec" arm, round-2 solo prompt), 1 run per task (fresh reference; r3 solo runs
  are reported as additional reference only).
Tasks: dev tasks T1b, T2, T3b, T4b (r3 bundles, unchanged). Reps: 2 per swarm arm per task, 1 solo per task = 20 runs.
Order: blocks by rep; within a block, tasks in a fixed shuffled order, arms alternating (C1 first on T1b/T3b, base4
first on T2/T4b); solo runs interleaved after rep 1. Concurrency 1-3 depending on the held-out calibration load.
Runner: /workspace/r4/tools/runner.py (= self3 runner2 + configurable port base), lab /workspace/r4/lab, names E1-*.

Metrics: quality = blind Claude judge with prereg/RUBRIC.md (r3 open rubric), 2 judgments/run (3rd if gap > 1.5,
median), anonymization per prereg/FAIRNESS.md F3 (PR.md and planning files removed for every arm); non-delivery = 0.
Collapse = non-delivery or quality < 3.0. Time = active_nf (freeze-excluded via heartbeat gaps > 60 s, else box-wide
silence rule); raw active and wall reported. Tokens = total input (uncached reported). Also: run end reason
(all peers ended / cap), number of END posts, branches left unmerged.

Decision rule (C1 becomes the base for E2 = KEEP):
  KEEP if (a) mean over 8 task-rep pairs of quality(C1) - quality(base4) >= +0.5, AND
          (b) collapses(C1) <= collapses(base4), AND
          (c) mean per-task active_nf ratio C1/solo <= 1.0 (C1 not slower than solo), AND
          (d) mean per-task input ratio C1/base4 <= 1.5.
  REJECT if quality difference <= 0 or (c) fails. Otherwise INCONCLUSIVE: add 1 rep per task per swarm arm (8 runs)
  once, then apply the same rule to all reps.
Report the paired 90% t-interval over the 4 task means as well (df=3; wide by design — E1 is a screening step;
the confirmatory test is the sealed held-out FINAL).
Infra failures (relay 503/empty catalog/CalledProcessError without delivery) are withdrawn and rerun; murmur failures
score 0 and are not rerun.

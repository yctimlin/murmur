# Orchestrators, context and configuration

Primary sources retrieved on 2026-10-16. This is a scoped survey, not an exhaustive census. Product documentation describes mechanisms; it does not establish comparative coding quality or cost. Where no comparable result is cited below, improvement over murmur is **unverified**. Repository merge behavior is **unverified** unless a source explicitly describes it.

## Systems

| System | Work split, coordination and context | Reported results and applicability |
|---|---|---|
| AutoGen AgentChat `SelectorGroupChat` | Selects a speaker from conversation history and participant descriptions, broadcasts the answer to participants, checks termination, and retains team context between tasks. Selection can be overridden with a function. [Official guide](https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/selector-group-chat.html) | Mechanism documentation, not an equal-budget coding comparison. Its broadcast design suggests a different context tradeoff from isolated workers; that is an inference, not a measured murmur result. [Same guide](https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/selector-group-chat.html) |
| Magentic-One | A lead orchestrator maintains a Task Ledger for plans/facts and a Progress Ledger for completion, next agent and stalls; prolonged lack of progress triggers replanning. Specialists cover browser, files, coding and terminal execution. [Architecture](https://microsoft.github.io/autogen/stable/user-guide/agentchat-user-guide/magentic-one.html) | The paper reports task completion of 38% on GAIA and 32.8% on WebArena, and 27.7% accuracy on AssistantBench. These are different tasks and model configurations, not repository integration or a 2×-token coding result. [Paper, introduction and Table 1](https://arxiv.org/html/2411.04468v1) |
| Microsoft Agent Framework | Offers graph workflows including sequential, concurrent, handoff and group collaboration, with checkpointing, streaming and human intervention. [Official repository](https://github.com/microsoft/agent-framework) | This establishes available orchestration mechanisms; comparable leaderless coding cost/quality is unverified. [Repository](https://github.com/microsoft/agent-framework) |
| CrewAI | Sequential crews pass prior task outputs forward, with explicit task context selection. Hierarchical crews use a manager to allocate, review and assess tasks. [Processes](https://docs.crewai.com/en/concepts/processes) | Its memory API supports shared and scoped context, automatically extracts facts after tasks, and recalls relevant context before tasks. These memory operations themselves can involve a model; savings for murmur are unverified. [Memory](https://docs.crewai.com/en/concepts/memory) |
| LangChain / LangGraph multi-agent patterns | Documents subagents, handoffs, skills, routers and custom workflows. Subagents normally have independent context and return results to a supervisor; history can be supplied when needed. Persistent subagent state is optional. [Patterns](https://docs.langchain.com/oss/python/langchain/multi-agent), [subagent context](https://docs.langchain.com/oss/python/langchain/multi-agent/subagents) | Documentation contrasts call count and accumulated context using illustrative scenarios, not a controlled coding benchmark. Do not transplant those illustrative savings to murmur. [Performance comparison](https://docs.langchain.com/oss/python/langchain/multi-agent) |
| Anthropic multi-agent Research | A lead delegates parallel research, and workers condense findings from separate context windows; plans and summaries are stored externally for continuity. [Engineering account](https://www.anthropic.com/engineering/multi-agent-research-system) | The vendor reports 90.2% improvement over single-agent Opus 4 on an internal research evaluation, and approximately 15× chat tokens for multi-agent systems versus 4× for single agents. **15× is relative to chat, not solo coding.** The authors explicitly warn that coding has fewer independent subtasks. [Same account](https://www.anthropic.com/engineering/multi-agent-research-system) |

## Engineering implications, with limits

1. **Leave model choice to the user and installed runtime.** This is a compatibility requirement from the brief, not a demonstrated speed optimization. Codex's `debug models` exports a raw catalog; selection belongs to its model manager, not the first JSON row. Verified in the provided 0.162.1 checkout, commit `092d3acd6bec3e3a14bdc7e7a2810ab628ab759d`: [catalog command](https://github.com/openai/codex/blob/092d3acd6bec3e3a14bdc7e7a2810ab628ab759d/codex-rs/cli/src/main.rs#L2093), [default selection](https://github.com/openai/codex/blob/092d3acd6bec3e3a14bdc7e7a2810ab628ab759d/codex-rs/models-manager/src/manager.rs#L845). The checkout was read locally; public availability of that exact commit URL is unverified.
2. **Separate evidence from assertion.** Revision-bound check receipts and explicit result state are promising because they turn a message into inspectable data. This is a proposal, not established token savings. Repetition and isolation are evaluation controls used by AutoGenBench; Magentic-One also reports a validation/test gap after setup/debugging, illustrating why held-out tasks matter. [Evaluation setup and results](https://arxiv.org/html/2411.04468v1).
3. **Do not assume another hierarchy is the answer.** The survey shows several central coordinators, but none of these retrieved sources establishes equal-budget superiority for a leaderless shared-repository task. That is a scope finding about the sources above, not a claim that no evidence exists.
4. **Treat a sync helper as convenience, not a proven cost lever.** Murmur's own G1+G2 experiment reports over 100 helper uses without reduced call count and failure to meet its keep rule. This argues against reintroducing the same mechanism as a claimed token fix. [Recorded experiment](evidence/lean-RESULTS.md), [pre-registration](evidence/lean-PLAN.md). These repository-relative references are the authoritative supplied evidence; they are not independently reproduced here.

## Configuration draft and validation

Draft `a4` removes fixed model and effort defaults. Precedence is explicit murmur flags, murmur TOML, explicit `model` / `model_reasoning_effort` from the user's `CODEX_HOME/config.toml`, then installed Codex defaults. Setup freezes explicit choices in metadata. With an unspecified model, catalog workarounds prepare all candidates rather than guessing which one Codex will select. With unspecified effort, per-model defaults remain untouched. No compaction setting is introduced. Evidence: [implementation](../src/murmur/cli.py), [configuration tests](../tests/test_config.py), [catalog tests](../tests/test_catalog.py).

This deliberately does not reimplement Codex's complete layered configuration loader or preserve project-level model overrides, named profile selection, plugins, or user instructions. Users can select a model through existing murmur flags/TOML. Codex's current official documentation describes broader precedence including project, profile, user and system settings; that live documentation can differ from the installed checkout. [Official configuration guide](https://developers.openai.com/codex/config-basic/).

Credential-free validation: initial full suite **37 passed in 9.16 s**, then one additional setup-freeze test brought focused configuration/catalog tests to **11 passed in 0.18 s**. These are local observed test outputs, not live agent performance measurements. Commands: `.venv/bin/python -m pytest -q` and `.venv/bin/python -m pytest -q tests/test_catalog.py tests/test_config.py`. Model calls: **0**; model tokens: **0**. No quality, speedup, token-ratio or cost target is claimed from these tests.

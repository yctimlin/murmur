## Analysis clarification retained for C1's later analyst

The runner initializes missing per-session usage to zero in its aggregator. Therefore a numeric zero in result.json is not itself proof of zero cost. Apply C1's existing missing-telemetry rule by auditing retained sessions when counters are absent, reset, inconsistent or suspicious: distinguish genuine reported zero from no usage record, label unavailable usage missing, and retain the unmodified result.json. This is measurement interpretation, not permission to change runner code or alter the preregistration after execution. Any derived telemetry repair must have its own append-only provenance entry and show both original and corrected values. No such C1 data exist at this review step.

The critique's requested block-means report is a useful descriptive complement to six raw runs and three A/A contrasts. It must not be called an identified random-effects decomposition with only three blocks/task. Likewise a run-mean crossing a wide per-run prior band is a declared forecast-screen failure, not a confidence statement. Multiple metric/task comparisons do not become an omnibus significance test. No candidate mechanism or default peer-count change is justified by this review.

# Screening tasks before hypotheses

- Question: Can phase A supply varied offline Python screening tasks with enough semantic edges to avoid a ceiling?
- Method: a2 owns a plain-folder document catalogue (336 distributed source files; expected 35 solo minutes) and an existing-repository event ledger repair (expected 40 solo minutes). a3 owns the independent long greenfield task. Each task has a public behavioral contract, deterministic input generator, and at least 30 independent hidden cases scored in a fresh temporary delivery copy. Tests use only Python's standard library. No lab or model run is performed in phase A.
- Prediction: untouched scaffolds score at most 0.30; competent solo implementations plausibly score 0.60–0.85 because basic cases coexist with explicit validation, ordering, persistence, and atomicity edges. That difficulty target is a design hypothesis, not a measured pass rate; post-freeze lab data must test it.
- Raw-data path: research/tasks/{document_catalog,ledger_replay}/; setup and harness checks will be recorded separately.
- Result: design chosen before any mechanism hypothesis or protocol experiment. The plain folder models a large archive migration; the repository task models maintaining an existing event-sourced package.
- Decision: freeze behavior rather than tailor tests to a peer protocol. Peer a3 reviews both a2 tasks, and a2 reviews a3's greenfield task.

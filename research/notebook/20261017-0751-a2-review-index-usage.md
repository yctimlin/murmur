# Independent historical usage and timing review

- Question: Are the historical index's headline input/uncached/output counts supported by raw provider counters, independently of its response-summing code?
- Method: Read all 241 raw session files named by sessions.csv. For the 240 containing modern usage records, take the final `payload.thread_token_usage` directly, instead of summing per-response `payload.usage` as index_runs.py does. Compare each session and each run, then sum. Independently reconstruct capped-union active minutes from raw timestamps for all observable runs. Read index method definitions and implementation, including source association and phase precedence.
- Prediction: exact token agreement, apart from possible last-record/response-deduplication differences; timing agreement to six decimals.
- Raw-data path: each source path is in research/data/sessions.csv; independent executable research/tools/review_index_usage.py; results research/data/index-usage-review.json.
- Result: exact match in all 240 usage-bearing sessions and all run sums: **668,357,819 input; 22,209,979 uncached; 5,016,406 output**. No token mismatches and no active-minute mismatches. The 241st session (`self2/eval/failed-W1-a1-429`, 01a14316-b9cc-7962-98ad-2b156672466f) has no usage records. Current labels identify it as zero rather than unknown. Also found peer identities initially inferred from inherited /work cwd; raw session_meta.agent_path correctly identifies peers. Both issues sent to a1 for correction; neither changes observed token totals.
- Decision: headline provider-token totals independently reproduced. The index's phase categories and last-tool input charges are useful operational associations, not exact semantic token sources or causal costs; METHODS correctly says so. Excess timestamp gaps do not prove idle time. Review remains conditional on missing-session and peer-label corrections, to be recorded in a follow-up entry.

# Additional products and projects

Surveyed 2026-10-16. These are primary project documentation, author papers and repositories,
not independent replications. “Not verified” means this survey did not establish the property;
it does not mean the product lacks it. Unless a row says otherwise, no matched long-task
speed/total-token/quality comparison against a strong solo baseline was verified. Current
pages can differ from historical releases. The linked sources support the mechanism claims
in their row; recommendations are our inferences.

| Project and sources | Work split / coordination / merge | Context and reported results; relevance to murmur |
|---|---|---|
| [Claude Code subagents](https://code.claude.com/docs/en/sub-agents) | Main session delegates focused work; workers can use separate tool/permission settings and optional worktree isolation, then return results. | Own context windows keep large exploration output out of caller history. This is a mechanism for selective context, not proof that more agents cost fewer tokens. No matched long-task swarm result verified on this page. |
| [Claude Code agent teams](https://code.claude.com/docs/en/agent-teams) | Lead plus teammates, shared task list and mailbox; file-locking protects task claims. Documentation recommends separate file ownership to avoid overwrites, not automatic semantic merge. | Independent teammate contexts; documentation explicitly warns of higher token and coordination costs, especially sequential or dependency-heavy work. Transferable ideas: real claim state and optional lifecycle hooks. A lead is a topology difference from murmur. |
| [Amp context management](https://ampcode.com/guides/context-management) | Handoff starts a focused thread using relevant information extracted from the previous one. Referencing another thread lets a second model extract relevant content. Merge policy not established by this guide. | Selective retrieval/handoff rather than copying an entire transcript. A useful design alternative for future bounded work units; extraction itself consumes inference. No comparative numerical claim verified. |
| [Aider repo map](https://aider.chat/docs/repomap.html), [chat modes](https://aider.chat/docs/usage/modes.html) | Code/ask/architect modes separate discussing a change from making it; this is a coding-assistant workflow, not evidence of a leaderless multiwriter swarm. | Repository map provides key definitions and signatures rather than all file contents. Useful example of context selection; no swarm speedup inferred from editing benchmarks. |
| [MetaGPT repository](https://github.com/FoundationAgents/MetaGPT), [paper](https://arxiv.org/abs/2308.00352) | Product-manager, architect, project-manager and engineer roles follow structured standard operating procedures and intermediate artifacts. | The paper studies role/workflow coordination for software generation; the current repository documents a software-company metaphor. Its reported task results are not a matched replication of murmur's open-ended repository work. Structured interfaces are transferable; mandatory role ceremony is not justified here. |
| [ChatDev paper](https://arxiv.org/abs/2307.07924), [current repository](https://github.com/OpenBMB/ChatDev) | Communicative software-development agents; current ChatDev 2.0 organizes configurable workflows with runtime/tooling and memory modules. | The original paper and current workflow platform are distinct snapshots. Examples and author experiments are evidence of feasibility, not verified murmur-equivalent token efficiency. Explicit intermediate artifacts may help seams. |
| [gpt-engineer](https://github.com/AntonOsika/gpt-engineer) | CLI generates code from a project prompt or improves an existing directory; customizable preprompts. Peer merge policy not established. | Repository includes a `bench` interface supporting APPS/MBPP. These coding-task evaluations are not long-running multi-agent integration results. Relevant as a lightweight comparison baseline, not a swarm architecture to copy. |
| [Sweep](https://github.com/sweepai/sweep) | Current repository README says the team is building a JetBrains coding assistant. This survey did not verify the historical issue-to-PR bot's present orchestration/merge behavior. | Context, current parallel coordination and matched results unverified. Included because the brief explicitly names it; the product's current description should not be replaced with an old remembered architecture. |
| [mini-SWE-agent](https://github.com/SWE-agent/mini-swe-agent) | Minimal bash-only agent; independent `subprocess.run` actions, no orchestration stack required. | Linear append-only history, inspectable trajectory. Repository reports SWE-bench results, but those model/task-dependent numbers are not a matched swarm comparison and were not reproduced here. Supports keeping a capable simple baseline. |
| [Claude Squad](https://github.com/smtg-ai/claude-squad) | Terminal manager runs coding agents in separate Git workspaces, with change review before application/push. | Parallel independent sessions and human review, not automatically a communicating swarm. “No conflicts” in the README describes workspace isolation; it is not evidence that final semantic integration cannot conflict. No comparable quality/cost result verified. |
| [Conductor](https://www.conductor.build/docs) | Runs Claude Code, Codex, Cursor and OpenCode in parallel; each task has its own workspace/branch, terminal and diff; review/PR/merge/archive workflow. | Isolation and review are explicit product surfaces. Context transfer details and matched swarm results were not established by the introduction. This is the coding-workspace product, not the unrelated Conductor workflow engine. |
| [Warp orchestration](https://docs.warp.dev/platform/orchestration) | Parent/child agents across local/cloud execution, messaging, and supervisor, fan-out, verifier, DAG or swarm patterns. | Documented lifecycle/observability makes coordination state explicit. Exact semantic merge guarantees and matched token-quality results were not verified. Shows multiple topologies rather than a universally best swarm. |
| [Gas Town](https://github.com/gastownhall/gastown) | Mayor/worker/watchdog roles, persistent work tracking, and a Refinery merge queue. README describes batch verification with bisection to isolate failing changes; workers do not directly push main. | Persistent hooks and predecessor-session discovery support context recovery. Much more infrastructure than murmur. Queue/gate semantics are interesting future work, but performance and quality claims are unverified here. |
| [Ruflo / Claude Flow](https://github.com/ruvnet/ruflo) | Advertises hierarchical, mesh and adaptive topologies, specialized agents, federation and shared memory. | README links infrastructure benchmarks and advertises routing/memory metrics. These were not independently reproduced and should not be treated as coding-task quality/speed gains. Its broad system is outside the lightweight footprint selected for murmur. |
| [Swarms](https://github.com/kyegomez/swarms) | Framework exposes agent/workflow orchestration, including hierarchical swarms and tool integrations. | Useful topology catalog; repository feature claims are not independent efficiency evidence. Git semantic merge policy and a matched murmur-like evaluation were not verified. |
| [smolagents multi-agent example](https://huggingface.co/docs/smolagents/examples/multiagents) | Manager delegates web search to a managed agent while retaining code-interpreter tools. | Separates worker tools/context from manager work. Example is a multi-agent web task, not evidence for multiwriter Git merging or software quality. |
| [OpenCode agents](https://opencode.ai/docs/agents/) | Primary agents and subagents have configurable prompts, tools and permissions; users can invoke a subagent by mention. | Useful focused delegation/context interface. Parallel merge behavior and comparable numerical results were not verified from this page. |
| [Goose](https://github.com/aaif-goose/goose) | Extensible agent that can execute, edit and test with configurable model/tool integrations. | Relevant lightweight adjacent coding agent. This repository introduction does not establish a comparable autonomous swarm's coordination, merge or token-quality performance; those remain unverified here. |

Search discovery also surfaced Roo Code subtasks, but its documentation URL
<https://docs.roocode.com/features/subtasks> failed to load in this survey. No claims about
its current behavior are used. Discovery is necessarily bounded, not proof of an exhaustive
inventory of every project on the internet.

# Historical index measurement definitions

`python3 research/tools/index_runs.py` uses only the Python standard library and read-only Git commands. It writes `index.csv`, `sessions.csv`, and `drafts.csv`, sorted by stable keys with fixed CSV line endings, JSON key ordering and six-decimal timing. It neither runs candidates nor changes evidence. Run it again and compare hashes to reproduce. `python3 research/tools/diagnose.py` derives `DIAGNOSIS.md` from the index. All paths are local evidence paths, not links to external literature.

## Coverage and denominators

The discovery roots are `/workspace/{murmur-eval,explore,large,lean,lean2,val,big3,self,self2,self2/eval}`. `explore` supplies the C/D/F/L runs explicitly cited by the master log. Every immediate `ws/*/murmur.json` is included, including preserved `failed-*` attempts; every named solo folder is included. Research runs self/self6p and self2/r2 are included but excluded from task-comparison estimates. Judges are evidence about runs, not extra task runs. Nested commands issued while researching are not independent task evaluations. The index records a missing value as an empty CSV field; missing telemetry is never zero cost.

A run is one row. Peer identity uses session_meta.agent_path (an inherited working directory is not identity). The no-agent_path /tmp/wst preflight session under self/self6p is auxiliary_exec, not an extra task-solo arm. A session with no provider usage has blank counters and usage_status=unknown; run token_coverage=partial retains only observed usage. Per-session input, uncached input, output, active and wall minutes are both in `sessions.csv` and the `sessions_json` index column. Failed-attempt directory names, not their reused original run IDs, are stable identifiers. The empty-catalog attempt retains its outcome and task baseline although it has no sessions. Exit `turn_completed` for a solo is a preserved JSON protocol outcome, not a known OS exit code. Swarm OS exit codes come from `logs/run.json`. Numeric zero exit and zero main commits are separate fields.

`engine_revision` is distinct from `task_base`. Most old configs recorded the task repository revision, **not the murmur revision**. Engine revisions/branch labels come from cited plans or preserved arm worktrees. A branch name (including `main-at-run-unpinned`) is not presented as a recovered exact SHA. Historical moving branches cannot be pinned retrospectively from the available metadata.

## Time

`active_min` is the sum of `min(120 seconds, next_timestamp - timestamp)` across the **sorted union** of all session events. This reproduces the historical gap-capped convention, not CPU utilization or actual working time. A model thinking quietly, a provider stall and a box pause are indistinguishable from timestamps alone. Capping can also underestimate legitimate long work. `wall_min` uses run start/end when retained, otherwise session span; it includes pauses and hangs. `harness_seconds` is separately retained because older harnesses excluded pauses inconsistently. `wall_minus_active_min` is unobserved/gap time plus startup/shutdown, **not proven idle**.

The eight `phase_*_peer_min` fields decompose the sum of capped **per-session** spans (peer effort, including root). They are additive to each other; they are **not additive to run active or wall time** because peers run concurrently. Each event interval is attributed to the most recent tool call. Rule precedence: rank/vote board post; wait/poll; other board; Git integration; verification command; before first detected edit (exploration); after final main commit (polishing); remaining implementation (drafting). Drafting here includes implementation after a draft is selected. Standalone prose/thought inherits the previous tool's category. This is a deterministic operational approximation, not semantic annotation or causal time saved by removing a phase. Literal shell commands are extracted from JSON/JavaScript tool arguments before classification, so board prose and reading a test filename do not count as executing a test. Mixed shell commands use the first matching priority (edit, actual test command, Git sync, Git read, file read, other); calls without literal shell commands use edit/wait/board/other. Dynamically constructed commands can remain other. Inline assertions and mixed-purpose calls still prevent exact semantic attribution. The classifier exposes all eight phases, including zeros. `excluded_gap_min` sums per-session excess over the cap and is likewise concurrent peer time.

## Tokens and sources

Modern sessions use deduplicated `token_usage_record.payload.usage` by response ID. Older sessions use positive changes in cumulative `token_count.info.total_token_usage`; duplicate snapshots are ignored, resets are counted. `input`, `cached`, `uncached=input-cached`, and `output` are observed provider counts. They are not estimates. Missing/provider-unreported requests are outside observed usage. The modern method recovers one final 22,807-input response in self2/W1-orig missing from the old report's last token_count snapshot.

There is **no exact tokenizer/source-span accounting in these logs**. We therefore do not fabricate a partition of billable input into shell, file, board and model tokens. Instead:

* `source_{shell_output,file_reads,board_reads,other_tool_output}_chars` partitions serialized tool-output characters by the corresponding call's classifier. File-read commands are a subset of shell operations, pulled into their own category. Board posts' acknowledgments are included with board reads; mixed shell output is classified as one unit. These are character counts, not provider tokens. Images/JSON/HTML and character encodings make chars/4 especially unreliable, so no such conversion is made.
* `call_<kind>_input` charges each observed model response's **entire input context** to its latest preceding tool category. These are a cost association, not tokens newly introduced by that tool. Their sum equals observed input; overlapping content is repeatedly charged on later responses.
* `cached` is a directly measured lower bound on reused/prefix context (a prefix can also be recomputed uncached); it is not an avoidable-cost estimate. Model output has its own exact output counter, and can later become part of repeated input.
* `pre_main_input` is input before the first first-parent main commit; `post_main_input` is after the last. They bound chronology, not the causal costs of drafts or review. Neither is called "wasted tokens".

## Scores and quality localization

Retained final judge Markdown plus final JSON agent-message summaries supply old scores. Round-2 judge session logs have been withdrawn by the operator; we do not recover them. `/workspace/self2/eval/results.json` supplies its two-pass aggregate. Its P1 count is absent; `judge_p1` is blank, with a separately labeled risk-formula inference (`judge_p1_inferred_from_risk`) that may be unreliable under floor/clipping. `judge_dimensions_json` retains rubric dimensions and `judge_source` identifies provenance. Small document tasks have four dimensions, most code tasks five, and big3 six; pooled differences are descriptive heterogeneous comparisons.

Final retained artifacts take precedence over a transcribed results table. In particular lean/U2-new's final rubric is c=7,r=10,pr=7,d=8 with risk=5 (mean 7.4), while its historical table says 7.0. This non-baseline arm does not change the advisor's 16-pair mean. Blame attribution and seam assessments are a separate peer-reviewed inventory; a filename authored by one peer can still participate in an interface defect. A judge flag is not independently reconfirmed by this phase unless explicitly labeled.

## Draft redundancy

`drafts.csv` measures every retained `refs/heads/draft/*` against the run's task baseline. Counts include draft ref tips even when branch ancestry is absent from main after copying/cherry-picking. `draft_branches_not_ancestors` is a **lineage measure**, not proof of discarded work. `draft_nonfinal_added_lines` counts additions in files whose final blob differs; even a one-line improvement changes the blob, so it is deliberately not called waste.

The narrower `draft_absent_added_lines` counts the multiset of draft-added text lines not present at the **same path** on final main. It captures alternative implementations, superseded scaffolding and changes to adopted code. It can count moved/renamed text as absent and can miss rewritten behavior or duplicated lines appearing elsewhere in a file. Thus it is a reproducible **same-path textual non-retention proxy**, not a causal estimate of time wasted or semantic code reuse. Binary diff counts are zero because no line count is available. Distinct branches count their own contributions even when they duplicate each other. Selection can yield useful knowledge from unretained drafts; no savings claim follows.

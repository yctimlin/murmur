Build **workflow_store**, a durable offline Python workflow execution store for workers that can crash and retry requests. The repository contains a full contract in `SPEC.md` and public examples, but no implementation. Use only Python 3.11+ standard library at runtime. Provide `Store` and `StoreError` from `workflow_store`, a `python -m workflow_store` CLI, documentation, and useful automated tests. Keep it installable with `pip install --no-deps --no-build-isolation .` and support either a flat or src package layout.

The product must coordinate multiple processes through a SQLite file; keep workflows and their DAG tasks, lease work atomically, retry failed/expired attempts, reject stale workers, cascade dependency outcomes, and make client retries exactly idempotent. A batch is one transaction including iterable failures. Export/import must validate audit history by replay. The requirements deliberately interact: an expired lease, a duplicate old command, a failed batch, a reopened database, and two competing workers must all have coherent behavior. Implement all commands and the exact JSON/error shapes in SPEC.md. Do not substitute a process-local dictionary for durable cross-process state. Leave a concise `PR.md` describing behavior, design, and validation.

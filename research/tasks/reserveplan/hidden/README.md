# Grading design (operator only after task freeze)

74 equally weighted cases: 26 concrete schedules, 28 error contracts, validation/scheduling separation, immutability/repeatability, four fixed-seed grid-oracle workloads, and 14 CLI/import cases. The fixed-seed oracle uses minute arrays; the product must use event boundaries to handle the separate billion-minute case. All 25 bounded concrete schedules were checked independently against that oracle. No model or murmur runs were used to tune difficulty. The 60–85% solo target and 65-minute estimate remain uncalibrated design judgments.

The untouched input has no implementation and scores 0/74. Missing imports and candidate exceptions are ordinary case failures. The outer scorer copies the delivered tree into a fresh temporary directory (dereferencing links), disables bytecode writes, sets Python search paths to that copy, and runs the hidden suite in a subprocess with a 600-second total timeout. The suite uses only the Python standard library and does not need network access. The scored tree is never modified. Test diagnostics go to stderr; the final stdout line is the grading JSON. A crashed or timed-out whole suite receives 0/74. Each CLI invocation also has a 12-second timeout.

The package may use a flat or src layout. Installation is a product requirement but is not separately graded because availability of a packaging frontend/backend is not guaranteed by Python itself. Styling, PR.md, docs, and the module split are likewise deliverable requirements, not score proxies. Behavioral cases carry the grade.
